# Goal

1. MapTab 的布局从 `Stack` + 自定义 `buildStackBuilder` 改为 `HdsNavDestination` + `titleBar({ content: { stackBuilder } })` 模式，返回按钮由系统提供

3. 修复进入 MapTab 时前面页面闪烁的问题

# Current State And Constraints

## 问题分析

### 问题 1：布局改 HdsNavDestination titleBar 形式

当前 `MapTabPage.ets` 使用 `HdsNavDestination().hideTitleBar(true)`，把标题栏完全隐藏了，然后在 MapTab 内部用 `buildStackBuilder` 自定义了一个带返回按钮的标题栏。

正确做法是参考 `HomeListView.ets` 的模式：
```ets
HdsNavDestination() {
  // 内容
}
.hideTitleBar(false)
.titleBar({
  avoidLayoutSafeArea: true,
  content: {
    title: { mainTitle: '' },
    stackBuilder: (): void => this.buildStackBuilder()
  },
  style: {
    systemMaterialEffect: { ... },
    originalStyle: { ... }
  }
})
```

`titleBar` 自带返回按钮（`chevron_left`），无需手动添加。`stackBuilder` 允许在标题栏区域放置自定义内容。

### 问题 2：返回按钮

`HdsNavDestination` 的 `titleBar` 模式自带返回按钮和侧滑返回，`buildStackBuilder` 中应移除手动添加的 `chevron_left` 返回按钮。返回逻辑由 `HdsNavDestination` 的 `.onBackPressed()` 处理。

### 问题 3：进入 MapTab 时闪烁

根因分析：当用户点击"记录"Tab 时，HdsTabs 的 `onChange` 回调被触发，此时：
1. HdsTabs 已经将 UI 切换到 RECORD TabContent（空的 Column），导致视觉上短暂显示了空白页
2. `handleTabChange` 中调用 `openPage` push MapTabPage
3. 然后调用 `changeIndex(this.currentIndex)` 切回之前的 Tab

这个流程导致用户先看到空白 RECORD TabContent，然后看到 MapTab 推入动画，造成闪烁。

修复方案：不使用 HdsTabs 的 `onChange` 来拦截，而是直接监听"记录"Tab 的点击事件。具体做法：
- 不再通过 HdsTabs 的 `onChange` 处理 RECORD Tab
- RECORD TabContent 仍然为空占位
- 在底部 Tab 栏的"记录"按钮上添加点击事件监听，直接 push MapTabPage
- HdsTabs 的 `onChange` 中，如果 index 是 RECORD，调用 `changeIndex` 切回但不做 push（push 在 Tab 点击事件中处理）

但 `BottomTabBarStyle` 不直接支持 onClick。另一个方案是：

**推荐方案**：在 `handleTabChange` 中，当检测到 RECORD 时，**先切回原 Tab，再 push 页面**。关键是 `changeIndex` 和 `openPage` 的执行顺序和时序。

更精确的方案：在 HdsTabs 的 `onChange` 回调中：
1. 当 index === RECORD 时，立即调用 `changeIndex` 切回原 Tab（避免 UI 闪烁）
2. 然后用 `setTimeout(0)` 延迟 push MapTabPage（让 changeIndex 的 UI 更新先执行）

# Design

## 1. MapTabPage.ets — 改用 titleBar + stackBuilder

```ets
@Component
struct MapTabPage {
  @StorageLink(AppStorageKeys.TOP_INSET) topInset: number = 0;
  @StorageLink(AppStorageKeys.BOTTOM_INSET) bottomInset: number = 0;
  @StorageLink(StorageKey.HOME_PAGE_CONTEXT) appPageContext: PageContext = ...

  build() {
    HdsNavDestination() {
      MapTab({
        topInset: this.topInset,
        bottomInset: this.bottomInset
      })
    }
    .hideTitleBar(false)
    .titleBar({
      avoidLayoutSafeArea: true,
      content: {
        title: { mainTitle: '' },
        stackBuilder: (): void => this.buildStackBuilder()
      },
      style: {
        systemMaterialEffect: {
          materialType: hdsMaterial.MaterialType.IMMERSIVE,
          materialLevel: hdsMaterial.MaterialLevel.ADAPTIVE
        },
        originalStyle: {
          contentStyle: {
            backgroundStyle: { backgroundColor: Color.Transparent }
          }
        }
      }
    })
    .ignoreLayoutSafeArea(...)
    .backgroundColor($r('sys.color.background_secondary'))
    .width('100%')
    .height('100%')
    .onBackPressed(() => {
      this.appPageContext.popPage();
      return true;
    })
  }

  @Builder
  buildStackBuilder() {
    Row() {
      // 坐标文本 + GNSS 芯片（无返回按钮）
      Text(...)
      ...
    }
  }
}
```

关键变化：
- `hideTitleBar(true)` → `hideTitleBar(false)`
- 添加 `.titleBar({ content: { stackBuilder } })` 配置
- `buildStackBuilder` 移到 MapTabPage 中，内容只有坐标文本 + GNSS 芯片
- 返回按钮由 `HdsNavDestination` 的 titleBar 自动提供

**问题**：`buildStackBuilder` 内部引用了 MapTab 的 `titleText`、`subTitleText`、`isGpsLocked`、`satelliteCount` 等状态。如果 `stackBuilder` 在 MapTabPage 中定义，需要通过 props 传递这些数据，或者将 stackBuilder 保留在 MapTab 中通过回调传递。

**更好的方案**：将 `buildStackBuilder` 保留在 MapTab 组件中，通过 `@BuilderParam` 或回调传递给 MapTabPage 的 titleBar。

但 ArkTS 中 `@BuilderParam` 不能直接传给 `titleBar` 的 `stackBuilder`（它需要一个 `(): void` 函数）。

**最终方案**：将 GNSS 和坐标数据通过 `@Prop` 传到 MapTabPage，在 MapTabPage 中定义 `buildStackBuilder`。或者更简洁地：将 MapTab 中标题栏相关的状态暴露为 `@Prop`，由 MapTabPage 持有并传入。

实际上最简洁的做法是：MapTabPage 通过 `@Link` 或 `@Prop` 接收 MapTab 的标题栏数据。但这会导致循环依赖问题。

**最优方案**：保持 `buildStackBuilder` 在 MapTab 中，MapTab 通过 `@Builder mapTitleBuilder` 将其暴露，MapTabPage 在 `titleBar` 的 `stackBuilder` 中调用它。

但 `stackBuilder` 要求签名为 `(): void`，而 `@Builder` 方法只能在 struct 内部调用。

**实际最简方案**：将 `titleText`、`subTitleText`、`isGpsLocked`、`satelliteCount` 这些状态从 MapTab 移到 MapTabPage，MapTab 通过 `@Link` 引用它们，MapTabPage 在 `stackBuilder` 中使用。但这会打乱现有的数据流。

**最终选择**：保持 stackBuilder 在 MapTab 中定义，MapTab 接受一个 `@BuilderParam titleBarBuilder` 参数，MapTabPage 在构建 titleBar 时将 MapTab 的 builder 传入。

但 `titleBar({ content: { stackBuilder: () => void } })` 接受的是一个普通函数，不是 `@Builder`。我们可以在函数体内调用 MapTab 的 `@Builder` 吗？

不行 — `@Builder` 只能在 struct 的 `build()` 或其他 `@Builder` 中调用。

**最终最终方案**：最简洁的做法是把 `buildStackBuilder` 的内容移到 MapTabPage 中，MapTab 把标题栏数据通过 `@Watch` + `@Prop` 传给 MapTabPage。具体：

1. MapTab 新增一个回调 `onTitleDataUpdate?: (titleText: string, subTitleText: string, isGpsLocked: boolean, satelliteCount: number) => void`
2. 每次标题数据更新时调用此回调
3. MapTabPage 接收数据并更新自己的 `@State`

这太复杂了。**最简单有效的方案**：

**MapTabPage 直接使用 `@Link` 绑定 MapTab 内部的状态变量**。但这需要 MapTab 持有 `@State`，MapTabPage 用 `@Link` 引用 — 而 `@Link` 只能从父组件传入。

**真正最简方案**：既然 MapTab 内部已经有 `buildStackBuilder`，且用户要求"自定义信息buildStackBuilder保持不变"，我们只需：

1. MapTabPage 的 `HdsNavDestination` 改为 `hideTitleBar(false)` + `titleBar`，设置 `stackBuilder` 为空或极简
2. MapTab 的 `buildStackBuilder` 仍然保留，但不包含返回按钮
3. MapTab 的 build() 中仍然调用 `this.buildStackBuilder()` 作为覆盖层

但这样会导致两层标题栏重叠（HdsNavDestination 的 titleBar + MapTab 的 buildStackBuilder）。

**重新思考**：用户说"采用 hdsNavD 组件"。HdsNavDestination 的 titleBar 自带返回按钮和背景。正确做法是：

1. MapTabPage 使用 `titleBar({ content: { stackBuilder } })` 展示坐标和 GNSS 信息
2. MapTab 不再自己渲染 `buildStackBuilder`
3. 坐标和 GNSS 数据需要在 MapTabPage 中可访问

**数据传递方案**：将标题栏相关的 `@State` 从 MapTab 提到 MapTabPage，通过 `@Link` 双向绑定传给 MapTab。

```
MapTabPage (@State titleText, @State subTitleText, @State isGpsLocked, @State satelliteCount)
  └── HdsNavDestination.titleBar({ stackBuilder: buildStackBuilder })
  └── MapTab (@Link titleText, @Link subTitleText, @Link isGpsLocked, @Link satelliteCount)
```

MapTab 内部更新这些值时（通过 `onLocationUpdate`），通过 `@Link` 自动同步到 MapTabPage，MapTabPage 的 stackBuilder 也会自动更新。

这是最干净的方案。MapTab 中这4个状态从 `@State` 改为 `@Link`，初始值由 MapTabPage 提供。

## 2. buildStackBuilder 去掉返回按钮

在 MapTabPage 的 `buildStackBuilder` 中，只保留坐标文本 + GNSS 芯片，不包含返回按钮。返回按钮由 `HdsNavDestination.titleBar` 自动提供。

## 3. 修复闪烁

在 `HomeView.handleTabChange` 中，当 index === RECORD 时：
1. 先调用 `changeIndex(this.currentIndex)` 切回当前 Tab（避免 TabContent 切换的视觉闪烁）
2. 用 `setTimeout(() => { this.appPageContext.openPage(...) }, 0)` 延迟 push 页面

这样 HdsTabs 的 UI 不会切换到 RECORD TabContent，避免了闪烁。

# Risks And Compatibility

1. `@Link` 必须从父组件传入且初始值由父组件持有 — MapTabPage 需要声明对应的 `@State` 变量
2. `HdsNavDestination.titleBar` 的 `stackBuilder` 签名是 `(): void`，需确保 @Builder 可作为此回调
3. 标题栏高度变化 — 从自定义的 56vp 变为 HdsNavDestination 的系统标题栏高度，地图控件的 padding 计算需调整
