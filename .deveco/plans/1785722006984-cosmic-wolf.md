## Goal

参考 `/Users/buqianhe/Desktop/sample_in_harmonyos` 的标准 phone 模式 MVVM 目录结构，将 OutdoorAssistant 项目的 .ets 文件按职能归类，使目录结构更规范。

## 参考标准（sample_in_harmonyos feature 模块）

```
ets/
  common/        ← 模块内共享常量（如 DiscoveryConstant）
  component/     ← 可复用 UI 组件
  constant/      ← 全局常量（如 CommonConstants、BannerConstants）
  model/         ← 数据模型（如 BannerData、DiscoverData）
  service/       ← 业务逻辑/数据服务（如 DiscoverService、MineService）
  view/          ← 页面视图（如 ExplorationHomeView、MineHomeView）
  viewmodel/     ← 视图模型/状态
  util/          ← 工具类
```

关键原则：
- **按职能分类**，不按功能模块分类
- `view/` 放所有页面视图组件
- `model/` 放数据模型和接口
- `constant/` 放全局常量/枚举
- `component/` 放可复用的 UI 组件

## Risks And Compatibility

- **router_map.json 路径错误** → NavPathStack 路由失败，必须精确更新
- **main_pages.json** 的 `pages/SplashPage` 不受影响（SplashPage 未移动）
- **Import 深度变化**：从 pages/tabs/ 移到 view/ 后，相对路径从 `../../` 变为 `../`，需逐一确认
- **common/ 目录删除后**：确认无其他文件引用该目录下的文件
